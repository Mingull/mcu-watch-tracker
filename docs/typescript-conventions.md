# Typescript Conventions

- Use strict typing wherever possible.
- Prefer `const` over `let` for variables that are not reassigned.
- Use explicit return types for exported functions and public APIs where they improve clarity.
- Allow TypeScript to infer straightforward local function return types.
- Avoid using `any` type unless absolutely necessary.
- Prefer type aliases for unions, intersections and utility types over interfaces.
- Follow consistent naming conventions for variables, functions, and types.
- Use camelCase for variables and ordinary constants.
- Use PascalCase for type names.
- Use UPPER_SNAKE_CASE for true module-level constants representing fixed configuration values.
